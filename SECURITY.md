# Настройки безопасности

## Локальный запуск

Скопируйте `.env.example` в `.env`. Docker Compose читает этот файл автоматически.
Для запуска Node.js вне Docker передайте переменные окружения самостоятельно.

На Linux подготовьте доступную пользователю контейнера папку данных:

```bash
mkdir -p data
sudo chown -R 1000:1000 data
chmod 700 data

docker compose up -d --build
```

Откройте http://localhost:3000. По умолчанию порт доступен только на этой машине.
Для доступа из локальной сети установите `BIND_ADDRESS=0.0.0.0` и добавьте точный
адрес сайта (например, `http://192.168.1.10:3000`) в `ALLOWED_ORIGINS`.

## Публичный Linux-сервер

1. Направьте DNS домена на сервер. Установите Caddy на хосте; пример —
   `Caddyfile.example`. Разрешите входящие порты 80/443 и настройте Caddy.
2. В `.env` укажите `ALLOWED_ORIGINS=https://ваш-домен` и `COOKIE_SECURE=true`.
   Оставьте `BIND_ADDRESS=127.0.0.1`, чтобы приложение было доступно через прокси.
3. Перезапустите приложение: `docker compose up -d --build`.
4. Откройте сайт по HTTPS, создайте комнату и отправьте друзьям «Копировать ссылку».

HTTPS не включается одной переменной COOKIE_SECURE: нужен настроенный TLS-прокси.
С включённой Secure cookie вход через обычный HTTP работать не будет.

## Что защищено

- Сервер выдаёт подписанную cookie HttpOnly / SameSite=Strict, на HTTPS — Secure.
  Публичный playerId не даёт права входить от имени владельца. Сессия действует
  30 дней; после её истечения пользователь получает новую личность.
- Ключ подписи хранится в `data/session-key` с правами 600, сохраняется между
  перезапусками. Не публикуйте его. Удаление ключа сбрасывает все сессии.
- Старые clientId из localStorage не принимаются как доказательство личности.
  После обновления пользователям потребуется заново войти; автоматически
  присвоить им прежние роли без прежнего секрета нельзя.
- Вход нового участника в приватную комнату всегда требует случайный токен приглашения.
  Участники комнаты могут делиться приглашением; оно даёт право входа, не права хоста.
- Общий список комнат выключен; даже при включении содержит только публичные комнаты ожидания. Проверяются Origin, типы входящих событий,
  размеры сообщений и частота запросов; ограничения действуют и на Socket.IO.
- Контейнер работает без root, с ограничениями ресурсов, без capabilities,
  с файловой системой только для чтения (кроме data и временных файлов).

## Переменные .env

| Переменная | По умолчанию | Назначение |
|---|---|---|
| ALLOWED_ORIGINS | localhost и 127.0.0.1:3000 | Точные адреса сайта через запятую, включая схему и порт |
| COOKIE_SECURE | false | true только при HTTPS |
| MATCH_START_DELAY_MS | 15000 | Отсчёт автозапуска публичной партии после набора минимума |
| PUBLIC_ROOM_LIST | false | Разрешить API списка публичных комнат ожидания |
| MAX_CONNECTIONS | 200 | Максимум одновременных Socket.IO-подключений |
| MAX_ROOMS | 500 | Максимум хранимых комнат, включая завершённые |
| EVENTS_PER_MINUTE | 180 | События на личность в минуту; на IP — в 10 раз больше |
| JOINS_PER_MINUTE | 30 | Попытки входа/восстановления на IP в минуту |
| CREATES_PER_HOUR | 10 | Создания комнат на IP в час |
| CONNECTIONS_PER_MINUTE | 120 | Подключения и запросы сессии на IP в минуту (отдельные счётчики) |

IP определяется по прямому TCP-соединению. За прокси все пользователи могут
учитываться под одним IP; настройте лимиты под размер компании. Заголовок
X-Forwarded-For намеренно не используется без отдельной настройки доверенного прокси.
Счётчики живут в памяти и сбрасываются при перезапуске; это не защита от распределённого DDoS.

Делайте резервные копии data и ограничьте доступ к ним: там хранятся чат и секреты
партий. Когда достигнут MAX_ROOMS, архивные комнаты нужно удалять администратору
при остановленном приложении или увеличивать лимит. Автоудаление не включено.

Периодически выполняйте `npm audit --omit=dev` из server и обновляйте зависимости
и базовый образ, проверяя тесты. Не меняйте владельца данных на общедоступные права 777.

Настройки Socket.IO сверены с [официальной документацией](https://socket.io/docs/v4/server-options/).
Базовый Docker-образ переведён на Node.js 24; сроки поддержки — в
[графике релизов Node.js](https://github.com/nodejs/Release).

## Публичный подбор и приватные комнаты

«Найти игру» допускает гостей с защищённой сессией: игра выбирается заранее,
сервер случайно выбирает только публичную комнату ожидания нужной игры.
Начавшиеся и приватные комнаты исключены из подбора. При отсутствии свободной
комнаты создаётся новая; хоста в ней нет. После набора минимума начинается
отсчёт MATCH_START_DELAY_MS. Потеря минимального состава отменяет отсчёт.
Decoder допускает 3–8 игроков; Ticket to Ride — 2–5; Codenames — 4–8.

«Создать приватную комнату» доступно без регистрации. Хост выбирает игру внутри
и запускает её. Вход по одному номеру невозможен при любых настройках:
REQUIRE_INVITE больше не используется, приватное приглашение обязательно.
Старые комнаты без поля visibility восстанавливаются как приватные.

Выйти можно на любом этапе. Выход последнего подключения участника во время
партии завершает её для всех; уход зрителя партию не прерывает. При потере
связи запись игрока сохраняется без таймера, в том числе после перезапуска
сервера. DISCONNECT_GRACE_MS больше не используется. Вкладки одного игрока учитываются совместно. После публичной партии
каждый может найти новую игру или выйти; приватную повторно запускает хост.

## Возврат и завершение при отсутствии игрока

На главной странице сервер показывает только комнаты текущей защищённой сессии.
«Вернуться в игру» восстанавливает роль; для завершённых партий доступен просмотр
результата. Осознанно покинутые комнаты в этот список не входят.

Если участник офлайн, в публичной партии любой оставшийся участник может завершить
её с подтверждением. В приватной комнате это делает хост; если сам хост офлайн,
такое право получает другой участник. Зрители не получают это право. При завершении
приватной партии в отсутствие хоста инициатор становится хостом для следующей игры.
Если партия закончилась естественно при офлайн-хосте, другой участник может
вернуть комнату в лобби и принять роль хоста.

Ограничение сессии браузера (30 дней), удаление cookie или ключа подписи по-прежнему
прекращают возможность подтвердить личность. Само отсутствие игрока таймером не ограничено.
